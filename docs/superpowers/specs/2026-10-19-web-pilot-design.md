# 膳算手机网页版与 PWA 内测设计

日期：2026-10-19。文档状态：技术路线及完整设计已由用户确认；尚未实施联网改造或部署。

## 1. 已确认的目标与本次设计边界

把当前自己使用的膳算，演进为在手机浏览器中使用的联网营养与生活管理工具。首批为本人和10位朋友，共11个独立账号；只面向中国大陆，以个人主体准备服务，每月运行预算上限100元。现有电脑本地版继续可用，正式个人资料不自动上传。

用户已确认：复用React界面和FastAPI业务规则，先完成手机自适应网页，再提供浏览器支持条件下的PWA主屏幕入口。安卓安装包、iOS客户端与应用商店上架留待试用稳定后评估。网页可在Windows开发；上线后的服务独立运行，不依赖本人的电脑持续开机。

以下账号方式、保留期限、技术配置和容量指标随完整设计一并确认，作为实施默认值；资源核价或实际适用要求与之冲突时，应说明差异并更新依据。域名、服务商、实际报价、外部AI及适用手续属于发布前的外部依赖，目前没有购买、开户、备案、上传资料或公网发布。

本设计细化[联网演进方案](../../online-evolution-plan.md)和[手机网页内测开发计划](../../web-pilot-development-plan.md)。原有[本地架构](../../architecture.md)、PRD与本地验收记录仍描述已经实现的电脑版本；本设计不把未来能力写成现有能力。

## 2. 方案选择与首版范围

比较过手机自适应网页、网页加PWA、网页封装安卓包三条路线。本轮采用网页加PWA：尽量复用现有业务，增加手机拍照和安装说明，减少首轮分发与维护工作。主屏幕入口是浏览器能力，不承诺所有浏览器都有安装按钮，也不代表已经发布应用商店安装包。

首版必须覆盖：邀请与账号、个人档案及草稿、饮食目标与健康限制、每日三餐及可选加餐、替换与分量修改、照片识别和核对、个人问答、实际饮食与生活记录、快捷反馈、七天报告、可解释的次日调整、可管理的个人记忆、手动保存、个人备份与恢复、导出与删除、手机适配、费用控制及服务备份恢复。

首版不做：公开注册、付费订阅、食品商家和广告、社交分享、穿戴设备、HealthKit或安卓健康平台接入、推送通知、为每个人训练模型、复杂向量检索、原生安装包、跨设备离线编辑合并、当前本地资料自动迁移。备份恢复不能恢复其他账号的数据；未来本地资料迁移另做预览和确认流程。

## 3. 用户流程与页面关系

```text
打开HTTPS链接
  → 登录，或凭邀请注册
  → 阅读隐私说明，单独确认健康信息处理与AI使用说明
  → 首次建档并确认正式档案
  → 首页：实际摄入、下一餐、蛋白质、饮水、近期反馈
       ├─ 今日饮食 → 详情、替代、分量 → 确认吃过 → 实际记录
       ├─ 拍照分析 → 核对名称/配料/重量 → 确认吃过 → 实际记录
       ├─ 问答 → 引用本人条件 → 推荐卡片 → 预览后替换计划
       └─ 更多 → 记录 / 反馈 / 七天报告 / 个人档案与记忆 / 账号与数据
  → 快捷反馈与实际记录 → 明日调整说明 → 后续计划
```

保持目前的视觉风格、深浅主题、营养计算口径和八个日常页面。新增登录、邀请注册、账号恢复、会话管理和记忆管理。宽屏保留侧栏；手机延续简洁首页、更多菜单与底部问答/相机入口，所有模块有明确返回路径。

| 页面 | 首版数据与操作 | 必须出现的状态 |
| --- | --- | --- |
| 邀请、登录与恢复 | 邀请码、用户名、密码、一次性恢复码；退出和撤销设备 | 邀请失效或已使用、密码错误、限速、恢复失败、会话过期；不泄露账号是否存在 |
| 建档与个人档案 | 保留现有基本资料、生活状态、目标优先级、健康情况、过敏原、口味、食物形态、预算与时间；分步草稿、正式确认 | 未填写与明确无此情况分开；校验定位字段；草稿不覆盖正式健康限制 |
| 首页 | 只汇总实际记录；下一餐链接计划；饮水快捷增加；近期状态链接反馈和报告 | 无档案引导、无记录、未知营养、加载、失败重试；不编造健康评分 |
| 今日饮食 | 早餐、午餐、晚餐、可选加餐；食材、份量、估算、原因、成本与时间、至少两项合规替代 | 安全候选不足时说明不足；完成、跳过、替换、改量与实际记录严格分开 |
| 拍照分析 | 拍照或相册、图片、识别草稿、名称/配料/重量修订、营养重算和确认记餐 | 权限拒绝、坏图、格式不支持、超大小、排队、取消、失败、低把握、营养未知 |
| 智能问答 | 本人正式档案、相关实际记录和有效记忆的引用；会话、追问、候选卡片 | 无记录明确说明；AI未配置或超额时说明原因；模型输出不直接修改计划或健康事实 |
| 饮食与生活记录 | 日期、餐次、时间、食物和分量；饱腹感、喜好、不适可选；饮水、睡眠、运动、测量 | 补记、编辑、删除、空日期、多设备冲突；缺失值不补零 |
| 每日反馈 | 快捷点选饱腹感、精力、口味、执行困难和不适；补充文字可选 | 不要求逐项填满；不预选“无不适”或伪造反馈；显示保存和明日调整结果 |
| 七天报告 | 热量、蛋白质、记录完成范围、生活和体重趋势、主观感受、执行困难与建议 | 区分实际、估算、缺失；当天未结束不冒充完整日；无数据提供记录入口 |
| 个人记忆 | 内容、来源日期、确认/推测、是否生效；修改、暂停、删除与停止记忆 | 无记忆、来源已删、纠正已生效；删除后旧摘要不得重建相同记忆 |
| 账号与数据 | 保存状态、手动保存、个人备份/恢复、导出、账号删除、设备会话、隐私说明 | 身份复核、备份处理中、下载过期、恢复预览、失败保持当前数据、删除传播状态 |

## 4. 系统拆分与现有代码复用

```text
手机浏览器 / PWA
  → HTTPS入口：同源网页和 /api
  → FastAPI联网应用：认证 → 授权 → 校验 → 营养业务 → 当前账号存储
       ├─ PostgreSQL：账号、会话、个人实体、版本、任务与用量
       ├─ 私有对象存储：加密照片和个人备份
       └─ 持久任务工作进程 → 大陆可访问的受控AI服务
离机加密备份：数据库 + 附件清单 + 删除清单 + 密钥恢复材料
```

采用单区域、小型服务器的起步方案；网页入口、API和PostgreSQL可共用一台服务器。工作进程与API分开，初始AI并发设为1，队列持久化在PostgreSQL，避免首版引入Redis、微服务或GPU服务器。实际规格、连接池大小和并发上限通过11账号压测后设定。

新增独立联网应用入口、环境配置与依赖清单，不能通过放开当前本机端口发布。联网进程不初始化Windows SQLCipher库、DPAPI或Ollama；缺少数据库、密钥、允许来源等必要配置时启动失败，不回退到正式本地库。测试、预发布和正式环境使用不同配置、数据与密钥。

现有领域逻辑通过明确的存储接口复用：按账号get/require/list、带版本put/delete、事务、幂等操作、历史、实体关联和照片关联。当前少量领域函数直接调用SQLite SQL，需要先改为有测试覆盖的存储接口；本地适配器继续用原SQLCipher，联网适配器用PostgreSQL。不会向当前全局app.state.store临时切换用户。

API依赖从已验证会话创建不可变的当前用户上下文和存储对象。后台任务也必须携带用户、输入版本和数据修订号；不能复用本地单用户全局锁或数据代编号充当多人授权。

## 5. 邀请、身份与会话

默认采用邀请码注册、用户名密码登录、一次性恢复码恢复，暂不接短信或第三方登录。用户名只用于登录，不要求公开姓名；注册时告知恢复码丢失且无法登录后，没有通过个人健康资料找回账号的通道。

本人账号加10个朋友名额。邀请码随机产生、数据库仅存摘要，默认7天有效、一次兑换；兑换与账号创建在同一事务锁定名额。邀请码只能加入，不能读健康资料、登录已有账号或重置密码。管理页面只显示邀请、账号状态和必要用量。

首个本人账号由受控服务器初始化命令创建，交互设置密码并输出一次性恢复码；命令不记录密码，不通过公开注册页面赋予管理权限。初始化完成即关闭引导通道。无默认账号或固定初始密码。

密码采用成熟库的Argon2id哈希，不保存明文；密码默认至少12字符、允许粘贴与密码管理器，限制请求长度。恢复码随机生成、仅首次展示、只存摘要，一次使用后失效并重新生成。恢复流程原子消费恢复码、设置新密码、撤销旧会话，不能靠姓名、疾病、手机号猜测或管理员查看健康记录恢复。

会话使用服务端随机令牌，数据库只保存摘要。Cookie设置HttpOnly、Secure、SameSite=Lax、Path=/；写请求需CSRF令牌与精确Origin校验，登录和注册也处理登录CSRF。每次认证变化轮换会话和CSRF；默认空闲7天、最长30天后重新登录。提供退出当前设备和撤销全部设备。

登录、恢复与邀请兑换同时按账号和来源限速，不依赖单一进程内计数。只有受信反向代理可以提供客户端IP；错误响应不区分用户名不存在和密码错误。界面不保存密码、恢复码或令牌到localStorage、IndexedDB或URL。

账号切换时清除React Query缓存、图片blob、内存草稿、未完成重试和个人上下文；用跨标签页通知并在页面重新获得焦点时验证会话。过期或失效后停止提交，不能将上一账号的操作自动重放到新账号。

## 6. 数据模型、隔离与加密

首版沿用现有“类型 + 标识 + 日期 + 正文 + 版本”的业务实体组织，减少营养逻辑重写；认证、附件、关联、任务与费用使用独立关系表。下表是逻辑结构，不是已经执行的数据库迁移。

| 表组 | 必要字段与约束 |
| --- | --- |
| users | id、规范化唯一用户名、密码哈希、账号状态、时区、数据修订号、创建时间；默认Asia/Shanghai |
| invitations / recovery_codes / sessions / privacy_consents | 各自的摘要或版本、用户关联、有效期、兑换/撤销/同意时间；同意记录区分健康处理与AI处理 |
| entities | owner_id、kind、id、day、加密正文、key_version、version、创建/更新时间；主键(owner_id,kind,id)，version必须大于0 |
| entity_history | owner_id、kind、id、version、加密历史正文；按账号保存版本和删除前状态，不向其他账号开放 |
| attachments / entity_photos / links | owner_id、随机对象标识、大小、摘要、加密版本、状态；关联通过包含owner_id的复合外键连接实体和附件 |
| mutations | owner_id、request_key、操作类型、载荷摘要、状态、加密结果、时间；(owner_id,request_key)唯一，同键不同载荷返回冲突 |
| tasks / usage_reservations / usage_ledger | owner_id、类型、输入版本、加密载荷、状态、租约、尝试次数、取消时间；额度预占、结算和供应商用量关联到任务 |
| memories / memory_sources / suppressions | owner_id、类型、加密内容、确认状态、来源实体与版本、证据日期、启用/失效时间、修订号；保存删除抑制标记 |
| deletion_jobs / audit_events | 删除范围、无正文的对象清理进度、必要安全事件、结果和时间；不保存健康正文、原始问答或密码 |

所有个人查询和写入同时受服务层owner过滤和PostgreSQL行级安全限制，使用USING和WITH CHECK；表启用并强制RLS。运行角色不是表所有者、超级用户或BYPASSRLS角色，也不能自行修改策略。迁移和备份使用隔离凭据，不由公开API调用。

当前账号只能由服务端认证决定；每次事务用事务局部上下文设置身份，连接归还池后不遗留身份。未设置用户的查询默认拒绝或无数据；工作进程每次领取任务后在明确账号范围内执行。凭据、会话和全局调度表使用独立最小权限接口，不因全局任务领取权限获得任意健康正文访问权限。

按(owner_id,kind,day,created_at,id)等实际查询建立复合索引；关联外键列及任务状态/时间建立对应索引。分页列表有明确上限，报告按本人和日期范围读取，不能为11个账号扫描全库健康正文。连接池初始上限5，调度和维护预留连接；用真实PostgreSQL验证连接复用、RLS和并发，不用SQLite替身作为隔离验收。

敏感正文、照片和导出备份用带随机nonce的认证加密封装，关联账号、实体和密钥版本作为认证附加数据。数据库检索所需的owner、类型、日期、版本等元数据不伪称全部不可见；数据库卷、对象存储及备份同时要求静态保护。密钥与数据分开保存，恢复材料单独加密，日志不输出密钥。服务端处理时会解密数据，因此不宣称端到端加密或运营者在技术上绝不可能访问。

共享基础食物库和发布食谱为只读资源，先核对来源与再分发使用条件；用户自定义食物始终按账号隔离。没有许可依据的资源不能随网页对外发布，也不能以AI编造来源替代。

普通邀请管理者默认没有查看他人健康正文的界面或接口。基础设施维护人员具有系统层权限，须在隐私说明中如实说明管理边界，限制授权与访问记录。

## 7. 自动保存、手动保存和一致性

草稿默认在停止编辑800ms后按表单串行保存；新输入等待当前保存结束再提交，响应按版本和操作序号应用。无效正式值保留在草稿并提示校验，不能把未填写疾病或过敏原当作“无”。点击“保存档案并应用”才替换正式健康限制，并将受影响旧计划标记为待复查。

餐食、饮水、反馈和生活记录在对应确认或点选后提交；实际记餐始终需用户确认吃过。完成的草稿与已经持久化数据刷新、关闭或换设备后可重新读取。首版断网只保证当前页面的内存输入被保留；关闭浏览器前尚未送达服务器的输入不承诺恢复。

| 状态 | 页面行为 |
| --- | --- |
| 正在保存 | 显示进度，保留输入，防止同一操作重复触发 |
| 已保存 | 仅收到持久事务提交结果后显示，包含最近保存时间 |
| 结果待核实 | 请求超时或响应丢失时查询原操作结果，不能直接声称失败未写入或重新创建新操作 |
| 保存失败 | 显示原因和重试，使用同一个request_key，不清空输入或显示成功 |
| 版本冲突 | 返回409，保留本次输入并展示服务器新版本，由用户决定如何合并，不静默覆盖 |
| 登录失效 | 停止提交并要求重新登录；未保存内容只留在原账号内存范围，换账号时清除 |

保留手动保存入口，表单“立即保存”提交本页有效草稿或待保存编辑；涉及健康限制和实际记餐仍走确认流程。另提供“创建个人备份”按钮，明确只备份服务器已保存数据。有待提交内容时先提示处理，不能用备份成功冒充表单保存成功。

记餐、饮水增加、计划确认、照片确认和任务创建均采用按账号隔离的幂等标识。幂等结果与业务修改同一事务提交，载荷不符拒绝。保存结果与关联操作凭证随对应业务数据保留；记录删除后仍保留防重放标识，不让迟到重试重新创建已删内容。账号彻底删除才清除相关凭证。

计划确认与实际记录、照片确认与关联、饮水增量、反馈与调整的关键写入保持原子性。用数据库唯一约束、条件更新和必要行锁处理并发；版本不匹配不自动扩大重试。业务日期默认按Asia/Shanghai计算，事件时间用带时区时间戳；跨午夜刷新默认日期，手选历史日期不被跳转。

## 8. AI、个人记忆和调整

普通计划、过敏排除、营养核算和报告统计继续由程序及有来源的食物库执行；图片理解和问答通过服务端调用受控AI。首批选型必须核对价格、处理区域、日志保留、训练用途和个人主体可用性；未配置时界面显示“AI服务尚未配置”，手动记录仍可使用。

请求顺序：验证账号及同意状态 → 读取本人正式档案、近7天相关实际记录、近30天必要趋势及有效记忆 → 急症规则 → 硬性过敏/健康过滤 → 目标、口味、食物形态、预算、时间与多样性排序 → AI受限选择/识别 → 结构化校验 → 程序核算 → 展示依据、估算与替代。禁止模型输出未经核对的营养数字、诊断、药物修改或任意工具操作。

照片识别不能确认隐藏配料、油盐糖、过敏交叉接触。允许修改名称、重量与配料，营养重匹配；未匹配指标显示未知。把握程度标为未经准确率校准的参考，不编造百分比。识别成功、问题回答或生成计划都不能自动增加实际摄入。

任务持久保存queued/running/succeeded/failed/cancelled/interrupted等状态。领取任务使用数据库锁及有限租约，失联任务不能无限执行；外部请求设置超时、尝试上限和最坏费用预占。结果提交前复核用户状态、取消状态、档案/照片版本和数据修订号。用户删除、改档案或恢复数据后，迟到结果不得覆盖新内容。取消不等于供应商停止计费，页面如实说明。

个人记忆区分明确表达与系统推测。用户明确的普通偏好可按来源记录；从行为归纳的偏好先展示待确认，确认后再长期生效；一次跳过不推断为讨厌。疾病、过敏、药物、孕期和医学结论仅能由用户明确确认进入正式档案。用户可纠正、暂停、删除记忆和停用记忆功能；基本安全仍依赖正式健康档案。

删除记忆时处理来源、摘要和推荐缓存，并保存最小抑制标记，防止旧来源立即重建同一条记忆。该标记本身属于用户数据，可随账号一起删除。来源或正式档案变化时让冲突记忆失效；个人反馈不能改变所有用户的安全规则。

次日调整沿用现有保守策略，只修改未来未执行计划，显示原因、具体改动、主要营养估算前后差及恢复入口；同一依据不累加调整。复杂健康状况或证据不足时保留待核对；历史实际记录不被改写。

## 9. 照片、手机交互与PWA

相机权限只在用户点击时请求；拒绝后可选相册或手动记录。保留JPG/PNG/WebP与当前12MB上限，服务端同时检查实际类型、像素数与解码资源，压缩并移除EXIF定位等元数据。AI使用受限尺寸图片。HEIC等未验证格式明确提示转为支持格式，不把手机选到文件等同于识别支持。

照片和备份使用随机对象名、私有桶和加密对象。首版图片由同源鉴权接口核对归属并传输，不在页面暴露永久公共链接；不存在和无权访问都返回统一404。上传、识别、取消、修改与删除均有对应状态，上传中断遗留对象由受控清理任务回收。

小屏至少验证320、390、430 CSS像素及桌面宽屏。主要触摸目标至少44 CSS像素，文字放大200%仍能完成主要操作；软键盘不遮挡保存或聊天输入，安全区与悬浮栏预留空间。表格可在局部横向滚动，页面不横向溢出。保留减少动态、减少透明度和系统主题支持。

PWA仅允许缓存明确清单内的带内容摘要静态JS/CSS、图标和无个人数据的离线说明页。API、登录响应、健康资料、照片、问答、导出和备份全部网络访问并使用private/no-store；不写入Service Worker Cache、localStorage或IndexedDB。应用HTML不嵌入个人健康数据，刷新必须重新验证身份。

离线说明页提示连接网络后继续，不显示缓存健康详情或伪造保存。首版没有跨重启离线编辑队列和后台自动上传。主题等非健康外观偏好可按现有方式本机保存。

更新准备好时提示“新版本可用”；存在未提交输入、拍照或恢复操作时不强制激活Service Worker或刷新。确认安全后切换版本，保留兼容的服务端协议窗口；旧静态缓存清理不触及业务数据。Android、iPhone和微信内置浏览器分别记录支持能力，安装提示不适用时提供浏览器打开说明。

## 10. 数据权利、备份与保留期限

健康信息处理单独告知用途、范围、保存位置和用户权利；AI处理另说明会发送哪些最少资料、供应商及用途，未经相应确认不发送图片或健康上下文。拒绝AI仍可使用已同意范围内的手动记录。撤回健康处理后停止该处理并提供导出与删除路径，不能继续生成相关推荐。

已确认的首版默认期限：正式档案、实际记录、对话、已确认记忆和照片持续保留至用户删除或注销；不因一次不活跃自动删正式资料。未完成且30天未编辑的草稿可过期清除，提前在草稿说明中标明。对话和照片支持单独删除。

为控制空间，初始每账号照片及个人下载备份合计100MB，11账号合计不超过1.1GB的应用分配额度；接近上限提示，超过时停止新上传或新备份，已有记录与导出仍可使用，不静默删除旧照片。供应商实际容量与备份成本另核价。处理失败的上传临时文件24小时内清理；下载导出临时文件24小时过期且每次下载需鉴权。

每日自动执行离机加密备份，滚动保留30天；个人主动创建的服务器备份同样保留30天，并标注失效日期。用户下载到自己设备的副本由其管理。非敏感排障日志默认7天，最少安全审计事件默认180天，发布前按适用要求核对；不以日志保留为理由收集健康正文。供应商侧日志及留存必须另行核实并告知。

个人备份为版本化、带校验的加密包，仅包含本人已保存的业务资料与附件，不含密码、会话、恢复码、其他用户数据或服务器密钥。恢复需重新验证密码及备份密码，先检查格式、大小、解密、完整性、照片清单和账号匹配，展示范围并明确确认整体替换本人数据。

恢复先创建本人当前快照，将待恢复数据写入隔离暂存区，校验后原子切换该账号数据修订号；失败保持上一完整状态。阻止并行恢复与写入，丢弃旧任务结果，清理记忆派生缓存。恢复不能触碰其他账号、还原旧登录凭据，或绕过已完成的删除抑制记录。电脑本地便携包不自动被云端接受为本人备份，另设迁移流程。

账号删除需重新验证身份和明确确认，先撤销会话、冻结新写入、取消任务及AI提交，再异步清理实体、历史、草稿、记忆、附件、缓存、个人备份及操作结果；在线副本目标24小时内清理。处于离机备份中的副本最多随30天保留窗口退出，不能声称立即抹除；供应商留存以实际协议与可验证删除结果为准。

删除清单与备份分开保留最小信息，恢复整站时先回放比快照更新的删除状态，再允许服务对外访问。不得恢复已注销账号或已删除健康记录；必要安全日志仅保留最少非健康内容及其合法期限。

日常误删恢复与隐私删除须明确区分：普通记录删除后可暂留版本历史，界面如实说明；用户执行彻底删除照片、对话、记录或账号时，同步清理相关历史正文、幂等结果正文、派生记忆和个人备份，防重放只留最少标识。删除清单至少覆盖仍可恢复的全部备份时间窗口，离机副本按上述30天规则退出。

## 11. 接口与错误契约

沿用现有/api业务路径并在联网入口增加认证与当前用户依赖，避免无必要改写八个页面的数据协议。本地入口保留原单用户协议。只有会话、健康检查和必要认证流程可匿名访问；公开健康检查不返回目录、数据库、账号数或内部配置。

| 接口组 | 责任 |
| --- | --- |
| GET /api/session；POST /api/auth/register、login、logout、recover | 获取匿名或已认证会话状态和CSRF；邀请注册、身份验证、退出、恢复 |
| GET /api/auth/sessions；POST /api/auth/sessions/{id}/revoke | 查询本人的设备会话、撤销；不能查询其他账号设备 |
| GET/PUT /api/profile；PUT /api/profile/draft | 本人正式档案和版本化草稿；保留正式确认语义 |
| /api/plans、records、feedback、reports及现有生活记录路径 | 保留当前计划、实际、反馈与七天统计协议，均限定本人 |
| /api/photos、analyses、chats、tasks | 私有照片、识别核对、个人问答、任务查询与取消 |
| GET/PATCH/DELETE /api/memories；PATCH /api/memory-settings | 个人记忆与来源、纠正/暂停/删除、功能开关 |
| GET /api/operations/{request_key} | 本人的提交结果核实；不允许通过猜测标识读取其他用户结果 |
| /api/data/export、backups、restore、account-deletion | 异步导出、个人快照、校验/预览/确认恢复、删除及进度；独立于本地整库恢复接口 |
| /api/invitations、usage | 邀请管理者管理名额与必要费用；普通用户仅查询本人剩余额度 |

上述接口组用于划清责任；路径下的动作、参数、响应schema和兼容映射在对应模块的实施计划中固定，并以契约测试约束。浏览器不能通过传user_id、对象路径或费用参数改变授权或计费。

统一错误包含code、用户可读message、必要fields和无敏感正文的request_id。401提示重新登录；403用于CSRF或功能权限；404不暴露资源归属；409保留输入处理版本冲突；422定位字段或不支持图片；429提示限速或额度；503说明暂时不可用。异常不回显病历、照片、密钥、服务器路径或完整模型响应。

## 12. 费用、资源与公开访问前置条件

月预算沿用基础服务50元、AI25元、照片/离机备份/流量10元、预留15元；这是分配上限，未取得实时报价。域名年费按月折算，续费和最低计费周期需计入；不能用新人赠送额度证明长期可行。首轮没有应用商店开发者年费。

统一核价场景为11人、30天、每人每天3次照片及5次问答，即990次识别、1650次问答，另算摘要、重试、并发和备份。该场景不是已承诺的每日额度。根据实际模型价与最坏输入/输出长度计算可提供额度；核价超过100元时提交可审阅的调整方案，不直接购买或扩大预算。

每次AI调用前原子预占本人及整站额度，以供应商价格版本计算最坏费用，再按真实账单结算。未知结果先保留预占，不因超时立即释放并无限重试。达到上限停止新增付费任务，展示原因；手动记录、已有资料、导出和删除继续可用。禁止未授权自动充值，配合供应商可用的余额与额度限制；应用估算不是供应商账单承诺。

发布依赖：比较至少两家大陆服务商的真实价格和个人主体可用性；选择域名并实名；核实网站/域名、健康信息服务和AI使用的实际适用手续；部署HTTPS、私有存储和备份；完成隐私说明、服务联系方式、费用限制及真机验收。PWA不因没有商店安装包而自动免除适用要求。

目前缺少域名、服务器、外部AI和账号，不影响本地隔离开发及真实本机PostgreSQL测试；真实云端AI、正式HTTPS和公网真机结果必须在资源就绪后验证，不能以模拟输出或本地地址代替。采购、创建外部账号、提交实名资料、公网部署和发送邀请应分别在具体材料与费用可审阅后按用户授权执行。
