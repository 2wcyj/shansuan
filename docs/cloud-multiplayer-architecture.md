# 膳算云端多人版架构与隐私边界

- 状态：用户确认进入开发；生产部署仍需云账号、域名、备案和发布验收。
- 适用：在现有 Windows 本机版旁新增公网多人版本。旧版和旧用户数据继续独立运行。
- 目标：先邀请约 10 位成年人试用；安全和稳定性验收后再开放注册。

## 改造前的本机版基线

- React、TypeScript、Vite 前端调用相对地址 `/api`；Vite 只在开发服务器代理到本机 `127.0.0.1:18765`。
- FastAPI 后端的 `create_app(data_dir)` 为单进程、本机单档案服务；会话与 CSRF 在进程内产生，访问中间件只接受本机 Host/Origin。
- 存储为每个本机实例一个 SQLCipher 加密 SQLite 数据库和附件目录。数据库密钥用 Windows DPAPI 保护；启动器与手机配对脚本依赖 Windows API 和 `msvcrt`。
- 模型由本机 Ollama 提供；照片和问答任务进入进程内任务队列。
- 产品没有账号、注册、密码重置、用户租户、云对象存储或公网运行时。

## 已实现的云端开发基线（尚未上线）

- 独立 Linux/FastAPI Docker 入口、非 root 容器、只读式 live/readiness 探针；最新本地镜像构建通过，无数据库时容器 `live=200`、`ready=503`。
- PostgreSQL 账户与租户表、Alembic 迁移、非 superuser 的运行角色、强制 RLS；账户认证与邀请、Argon2id、会话摘要、CSRF、安全 Cookie、限速和 SMTP 适配器。
- 隐私告知当前只是一份待法律审核的草案。云端 API 有版本化同意、状态、撤回接口和健康写入依赖；用户代理只保存 HMAC 摘要。
- 新增 AES-256-GCM 账户数据密钥包装接口、账户密钥表与通用加密实体 repository；生产适配器使用华为云 KMS，绑定大陆地域和具体 CMK ID，按账户 UUID 绑定（账户标识放在待加密明文内），支持 IAM 长期密钥与临时凭证。生产/预发布无配置或加解密探测失败时拒绝启动；真实华为云资源、IAM 委托身份和密钥轮换尚未创建或验收。
- Netlify 前端可配置 API origin，已有独立云端账户与同意页面；云端档案/草稿 API 已开始接入加密仓储，并验证双账户隔离、版本冲突、测量故障回滚及加密历史。档案与饮食计划的关联规则尚未接入，档案 UI 暂未开放。
- 饮食/生活业务 API、产品目录和基本账户 JSON 导出/数据库级账户删除已接入租户存储。照片已完成校验、应用层加密并写入华为云 OBS 私有桶；问答、附件导出/删除协调、备份及持久模型任务仍未实现。
- 会话与登录限流已支持华为云 DCS for Redis 共享存储，Redis 不可用时回退 PostgreSQL；修改密码会同时失效两端会话。
- 尚未创建云资源或公网部署。当前只能使用合成测试账户，不要输入真实健康资料。

## 目标架构

```text
用户浏览器
  ├─ HTTPS GET 静态前端 → Netlify（不承载健康数据 API）
  └─ HTTPS API + HttpOnly 会话 Cookie → 大陆云 API 域名
       ├─ FastAPI 服务（Linux 容器）
       ├─ PostgreSQL（托管或私网数据库，用户隔离）
       ├─ 私有对象存储（用户图片，短期签名 URL 或 API 代理）
       ├─ 云密钥管理服务（包封加密主密钥）
       └─ 独立模型工作进程（自托管，不向第三方 AI 发健康资料）
```

前端通过 `VITE_API_BASE_URL` 指向独立 API 域名，禁止 Netlify API 代理接收健康档案、照片或饮食记录。生产前端与 API 必须配置在同一注册域名下的不同 HTTPS 子域名（例如 `app.example.cn` 与 `api.example.cn`），不能用 Netlify 默认 `*.netlify.app` 域名进行最终 Cookie 验收，因为浏览器将其视为跨站第三方 Cookie。生产 API 只允许精确的前端 Origin；Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`，写请求沿用 CSRF 校验。静态前端不会包含密钥。

Netlify 前端和大陆 API 是两个独立服务。正式对大陆用户开放前必须从不同网络验证 Netlify 域名可访问性；若无法稳定访问，生产静态资源迁往大陆静态站点/对象存储与 CDN，Netlify 仅保留预览用途。大陆云资源、域名备案和网络配置待账号所有者办理。

## 账号和访问控制

- 试用阶段：管理员生成一次性、限次数邀请码；用户用邮箱和密码注册，每人独立账户。公开注册默认关闭。
- 扩大开放：启用公开注册前完成邮箱验证、找回流程、滥用防护和隐私审查。
- 密码使用 Argon2id 哈希，永不存明文；登录和敏感操作限速；会话随机、可撤销并设定到期；密码重置令牌一次性且短时有效。
- 每个业务实体、附件、AI 任务、幂等请求和备份都必须绑定 account_id。每次请求从已验证会话获得 account_id，不接受客户端传入的租户标识。
- 业务数据查询同时执行应用层 account_id 限定和 PostgreSQL 行级安全策略。授权失败按不存在处理，不泄漏其他用户对象是否存在。
- 管理员不得默认浏览用户健康内容。运营后台首期不提供健康数据查询功能。

## 数据和加密

- 数据库使用 PostgreSQL；记录表有强制 account_id 外键/复合索引，开启并强制 RLS。应用运行角色不能绕过 RLS，迁移角色与运行角色分离。
- 个人健康内容和照片使用应用层 AES-256-GCM 包封加密：每账户独立 DEK，密钥由云 KMS/密钥管理服务包封；数据库和对象存储还启用平台静态加密，传输全程 TLS。
- 使用者认证、数据密钥及隐私同意记录存入独立认证/安全表，严格限制读取。日志只记不可逆用户 ID、请求 ID、操作结果和耗时，不写健康字段、请求正文、照片、访问令牌或密码。
- 每日加密备份存放在独立私有位置，设置保留与删除周期；定期做隔离环境恢复演练。账户删除执行主数据、照片、任务、缓存和待过期备份的可证明删除流程。
- 旧 Windows DPAPI/SQLCipher 数据不会自动上传。以后如需导入，由用户登录后主动选择现有密码保护的便携备份，在线传输 TLS，并在导入前展示将要写入当前账号的摘要；本机源数据保持不变。

## AI、照片和异步任务

- 第一方模型工作进程只运行在应用控制的云端网络，不公开 Ollama/模型端口，不把个人资料、问题或照片发到商业模型 API。
- 任务持久化在 PostgreSQL 或托管队列中，记录 account_id、状态和过期时间；访问任务结果再次校验 owner。worker 按用户解密所需上下文，任务完成后尽快清除临时明文和临时图像。
- 图片存储私有、随机对象键、大小与格式限额、恶意内容扫描。未经确认的分析结果仍不计入摄入；现有规则引擎、安全排序、统计口径和用户确认流程复用。
- 公开试用前完成模型延时、显存/CPU、并发和单用户配额测量；无容量时给出真实排队/不可用状态，不回退到第三方模型。

## 法规、隐私和发布边界

- 健康医疗信息按敏感个人信息处理。注册时单独、明确、可撤回地同意敏感数据处理；同意前不创建健康档案。隐私告知说明处理目的、种类、保存期、存储地、删除/导出方式、云端运维者与模型运行方式。
- 上线前完成适用的个人信息保护影响评估、数据处理协议、事件响应、权限审计与备案要求核验。公开发布需要产品负责人确认面向未成年人政策；试用默认仅允许成年人。
- 禁止广告 SDK、营销画像、在线支付和第三方 AI 数据传输。分析服务仅允许无健康内容的最低限度可用性指标，并须列入隐私告知。
- 生产域名、HTTPS 证书、备案、短信/邮件发送额度、服务器与 GPU/模型预算由用户本人审批和持有。

## 业务兼容与变更

- 当前本机 `create_app(data_dir)` 与其存储/DPAPI 继续作为原有桌面版入口，不用云凭据访问本机数据。
- 云端模式新增独立配置、认证中间件、租户存储适配器和部署入口；每个 API 服务从服务器认证会话推导当前账户。API JSON 业务语义尽量兼容 React 页面；必要的跨域 Cookie、上传/下载和账户生命周期接口另行版本化。
- 推荐规则、过敏过滤、营养计算、记录确认和报告代码优先共享纯业务域逻辑。依赖单用户全局 Store 的端点需明确改为请求级租户存储；不能通过全局可变 `app.state.store` 在并发账户间切换。
- 需要新增数据库表和 API；这是公网多用户与账号隔离的必要变更，旧本地数据库结构不被原地迁移或覆盖。

## 分阶段上线

1. **计划与云运行基线**：明确环境/密钥/域名清单，新增 Linux 容器入口与健康检查，不部署任何个人资料。
2. **认证与隔离基础**：账号、邀请、登录/登出、CSRF、安全 Cookie、限速、PostgreSQL 租户/RLS；两个账户端到端隔离测试。
3. **业务数据层**：按业务端点接入请求级 tenant store；每次只迁移一组接口与针对性测试，覆盖档案、推荐、记录、反馈、报告、产品与备份删除/导出。
4. **文件与 AI**：私有加密照片、持久任务、云端自托管模型，保留照片修改和用户确认逻辑。
5. **Netlify 前端**：配置生产 API Base URL、精确 CORS/CSP、SPA 刷新回退、环境变量、预览/生产隔离；部署无真实档案的测试环境。
6. **试用准备**：隐私文本、敏感信息授权、删除/导出、日志排查、备份恢复、限流、漏洞和并发检查；导入流程保持用户主动。
7. **十人邀请试用与公开发布**：分阶段发邀请，观察可用性且不记录健康内容分析；验收后用户本人开启公开注册、配置域名与备案并发布。

## 上线验收门槛

- 两个隔离账户端到端执行档案、记录、图片、对话、反馈、导出、删除；账户 A 对 B 的 ID、任务、照片、附件和备份均不可读取、修改或推断。
- PostgreSQL RLS 在应用运行角色下验证；直连数据库绕过应用查询也不能跨租户访问。
- 所有本机功能在云端完成兼容测试；未登录/同意前无健康信息写入；业务写操作有幂等保护和 CSRF。
- 数据库、对象、备份静态加密可验证，密钥轮换/恢复演练通过；没有健康内容进入日志、Netlify API 请求、分析和第三方模型。
- Linux 容器可构建、启动、迁移、健康检查和重启；Netlify 发布与 API Origin、TLS、SPA 路由、手机/桌面浏览器验收通过。
- 十位受邀用户试用期间没有高危/严重安全问题；公开注册门槛、隐私文件及域名备案由负责人签字确认。
