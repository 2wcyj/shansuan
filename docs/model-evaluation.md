# 本地模型能力验证

设备：Windows，Intel Core Ultra 5 125H，约31.5GB内存，Intel集显；当前使用CPU运行时。Ollama 0.40.6官方便携包，固定本机127.0.0.1:11439；不采用云端API。Qwen模型许可见 `third-party/qwen3-vl-license.txt`。

## 首轮失败与修复

首轮实际测试 `qwen3-vl:2b`（思考版，Q4_K_M），11个案例：中文说明1条、真实食物照片10张（披萨4、牛排3、寿司3）。照片由公开Food101派生测试包获取，只用于测试，不作为产品默认数据。

350个输出token上限时，多条输出完全耗在内部思考，最终内容为空；`think:false`和提示禁止思考没有解决。测试明确失败。失败原始证据：`.test-output/model-thinking-failed.json`。增加到1200个token的中文复测产生有效最终内容，但耗时约55秒且包含大量内部思考，不能以忽略空回复测试作为修复。

已选择同系列 `qwen3-vl:2b-instruct` 重新下载实测。该选择仍须通过相同的11个案例、中文问答及非空断言；在通过之前不标记P0成功。正式适配器必须拒绝空输出、结构错误、超时，不提供伪造成功结果。

## 复测结果

已完成修复：固定指令版模型及简短类别描述提示，不再使用思考版。最终manifest SHA256：`afc393e3572c07db0bc84aa460d928a16c75f3fbb9ca9e0dccc4fbd2dafb573e`，1.7B/Q4_K_M，主体和图像组件合计约1.93GB，运行时报告约2.02GB、VRAM0。

第一轮指令版类别断言仍失败：一张牛排被描述为肋排，没有给出稳定大类。保留原测试，修改提示要求明确大类及不确定性，再对全部11例重新运行。最终11例均非空，且每张包含相应食物类别描述；不代表具体肉种、配料或重量正确。单张热运行1.61—4.33秒；中文复测7.45秒，首次冷加载中文13.09秒。早期自由描述曾25—40秒，包含重复，因此正式流程仍需超时、取消及结构化校验。

证据：`.test-output/model-evaluation.json`；原失败`.test-output/model-instruct-first.json`、`p0-model-initial.xml`；最终pytest：`.test-output/p0-all.xml`，8项通过，包含真实中文调用。已真实停止运行时并确认不可用错误，没有伪造回复，随后重新启动。超时、任务取消与应用可继续手动使用将在P6/P8针对正式适配器验证。

运行时已绑定127.0.0.1，禁云并设置不可用外部代理；测试通过本机接口执行。模型许可Apache文本已保存。真实跨账户、物理断网及整机重启仍未执行，M0整体人工验收不标完成；按计划继续独立软件模块。

## 验证边界

测试照片仅覆盖三类食物，不能证明任意中餐都能识别。不能据图确定隐藏配料、实际油盐或真实克数，用户必须核对。置信程度使用定性参考，不能把模型自报百分比当校准概率。

程序将在模型停止、超时和取消时保留草稿并允许手动记录。所有图片缩到最长640像素后再送入本机模型，使用串行任务避免内存和CPU争用。

物理断网尚待人工验收。使用回环地址、阻断外部代理、无远程资源的自动化验证不能冒充已经拔掉网线或关闭系统网络适配器的结果。

## P6 正式服务验证

正式接口使用 qwen3-vl:2b-instruct 和 JSON 结构校验。照片先去元数据并加密，真实识别只提供候选名称/配料/克数及定性把握；营养由有来源的食物库计算。未匹配项留未知，用户确认后才记餐。模型不能访问任何写库或文件工具。

测试使用两个真实食物图片及两种独立档案，保留服务结果于 `.test-output/p6-real-ai.json`。加入超时、取消、重启中断、较新修订不可被迟到结果覆盖及重复确认测试。故障注入仅用于验证失败路径，不充当真实识别成功证据。

急救规则先于模型执行。测试发现“喘不过气”被不恰当地按“不过”拆句，已修复并保持原断言。规则覆盖有限，不是医学症状分类器，仍可能误报/漏报；紧急情况不应依赖此应用判断。


最终浏览器回归暴露一例：有真实当日记录的蛋白质问题，模型将提示中的内部字段名抄进中文正文，被Pydantic格式规则拒绝。原始测试输出与失败浏览器记录保留为`.test-output/chat-format-failure.json`、`browser-results-format-failed.json`。修复为更短的用户语义提示，去掉可被复述的内部字段指令，提示版本升为mna-2；保持原格式校验、真实成功断言，并将该合成档案及实际记录固定为`app/tests/fixtures/chat-day.json`回归测试。没有放宽输出约束或使用固定回复填补失败。


mna-2简化自由回复提示后仍有复述/误格式案例，保持原测试判失败。最终采用mna-3：真实本地模型理解问题并选择受限意图/执行步骤/可行食谱，程序据此组织有来源、引用实际记录的回答，不展示不受控自由文字。新增断言要求饥饿问题识别为hunger、实际蛋白质问题识别为protein。营养数字仅来源于程序计算，模型失败仍不生成回答。该方式限制开放式知识闲聊，超出已有数据的问题说明无法可靠回答；不是失败时用固定成功内容补位。

最终服务测试的四个真实任务耗时（照片两张、两档案提问）为：4.75秒、4.69秒、2.77秒、2.7秒。结构化照片通常比P0单纯类别描述更慢，首次使用应预留数十秒，任务提供状态和取消。
