# 本机使用说明

版本 0.1.0，2026-10-18。运行环境：当前 Windows 64位电脑、Chrome/Edge，Python 3.12。程序不需要登录，不使用云数据库或远程AI。

## 打开与停止

1. 双击项目目录中的 `启动.cmd`。等待本机服务准备好，浏览器会打开 `http://127.0.0.1:18765`。
2. 首次打开填写六步档案。之后重开直接进入首页。
3. 保留启动窗口。关闭浏览器不会删除数据；需要停止程序时双击 `停止.cmd`，或在启动窗口按 Ctrl+C。
4. 再次启动同一数据目录只打开现有应用。端口被其他程序占用时会报错，不会悄悄连接另一份数据。

应用不随Windows自动启动。电脑重启后再次双击启动文件即可。正在计算的AI任务关闭后不会承诺后台继续，重开标记为中断，可重试。

## 每天怎么使用

- **个人档案**：填写身体信息、目标、健康及过敏状态、饮食与做饭偏好。未填写与明确无不同。可输入自定义标签；无法可靠核对的疾病或过敏原会暂停自动推荐，手动记录继续可用。
- **今日饮食**：首次建档后自动生成适用的首日四餐。详情包含分量、营养估算、出处、做法、时间、参考成本与替代。替换或改计划分量不会增加实际摄入。吃过后核对实际食物与克数再确认。加餐可选，跳过不表示没有进食。
- **饮食记录**：手动记餐、补记过去日期，修改或删除。营养条目区分生熟；重量为可食部克数。包装食品可以录入每100g标签，kJ需除以4.184换成kcal。没有资料请留空，真实0可以填0。
- **生活记录**：在记录页填写饮水、醒来日的睡眠、运动、身体测量与感受。完整记录一天后可以勾选“已完整记录”，未勾选时统计只代表已知部分。
- **拍照分析**：上传JPG/PNG/WebP（最多12MB）或授权摄像头。点击本地识别，核对名称、生熟、配料与估算克数，保存修订后重新计算。未匹配项可以选择资料库或新增包装标签。配料文字只是核对备注，额外配料需要单列食物和重量才能计入营养。确认确实吃过后才会生成实际记录。
- **智能问答**：读取档案和近七天实际记录，显示真实参考条件。本地模型理解问题、选择执行步骤和已筛选方案，回答结合真实记录组织，营养数值由程序计算；超出已有饮食资料的问题会说明无法可靠判断。点击“放入计划”先预览餐次和替换内容，再确认；回复本身不会改计划或记餐。失败时保留问题历史，可重试。
- **每日反馈**：记录饥饿、口味、准备难度、不适、精力、暴食与特殊情况。不适可标记需要核对的食物，不代表已诊断原因。保存后检查明日方案，展示前后食物、克数及主要营养变化。手动改过的明日计划需确认；可以恢复调整前方案。
- **七天报告**：截至所选结束日的连续七天。空白不补零，空心点表示部分记录或当天未结束。均值仅用已结束、确认完整且该指标有完整营养资料的日期。只有两次及以上体重才比较差值，不称为长期趋势。

## 数据保存在什么位置

默认独立目录为 `%LOCALAPPDATA%\MyNutritionAssistant`，即当前账户的本地应用数据文件夹。个人档案页会显示完整位置。

- `active.json`：当前数据代指针，不含健康正文。
- `generations/<编号>/nutrition.db`：SQLCipher加密数据库，包含档案、记录、计划、反馈、问答和任务。
- 同目录的 `key.dpapi`：由当前Windows账户保护的主密钥；`photos/*.enc` 为加密照片。
- `backups/*.mnal`：本机备份。迁移前快照保存在 `backups/migration-*/`。

浏览器的本地存储、IndexedDB和缓存不是健康数据的保存位置。刷新、清除浏览器站点数据或更换浏览器不会删除这些独立文件。不要手动编辑或删除数据库、密钥与指针。正式数据目录不含演示数据；测试使用独立临时目录。

当前Windows账户可以无额外密码打开应用。磁盘加密不阻止当前已登录账户访问页面或由其主动导出数据；请保护Windows账户。

## 备份与恢复

1. 每日首次打开或写入前生成一份本机备份，保留最近14份；迁移/恢复前快照另外保留。备份失败会显示提示并阻止写入，已有内容仍可读取。
2. 在“个人档案 → 密码加密的便携备份”输入两遍至少10字符密码，点击创建。程序先校验，再交浏览器下载；按浏览器设置选择保存位置，确认 `.mnab` 文件已存在。建议保存在另一磁盘。
3. 本机 `.mnal` 备份依赖当前Windows账户；便携 `.mnab` 用独立密码，可在兼容环境重新封装密钥。**备份密码不能找回**。不要只复制 `key.dpapi` 当作跨账户备份。
4. 恢复时选择文件与密码，先点击检查；核对时间与条目数，再输入“整体替换”。继续前必须成功保存当前快照，然后整体切换，不合并两份数据。
5. 恢复失败、密码错误、损坏、版本不兼容或空间不足不会覆盖原库。校验票据有效10分钟，过期重新检查。切换被中断时，重开读取上一份完整数据或已完整提交的新数据代。
6. 恢复前快照可在“本机自动备份”中检查并恢复；迁移快照用于维护回退，不自动清理。旧数据代也会保留用于故障回退，删除全部个人数据时一起清除。
7. JSON/CSV“可阅读导出”未经加密，是查阅副本，不是可恢复的便携备份。请自行保管。
8. 删除全部个人数据需要输入明确文字，可选择是否同时删本机备份。外部另存副本需自己删除，普通文件删除不是磁盘安全擦除。

## 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| 模型未就绪 | 保留手动记餐；停止并重新启动应用，确认 `.tools/ollama` 与 `.tools/models` 仍在。程序不会自动联网下载 |
| AI等待较久 | CPU首次加载和复杂问题可能需数十秒；状态可查看、取消。取消后当前计算可能继续，但结果不会提交；之后才处理下一任务 |
| AI格式不可靠/未通过限制 | 这次没有成功回复，不会生成假内容；可换一种问法、核对资料或手动记录 |
| 未知营养或无安全候选 | 核对来源、生熟、标签和限制；不把未知当0，不降低过敏限制凑餐 |
| 资料/记录已被其他窗口修改 | 保留输入，刷新读取新版本再核对提交，避免互相覆盖 |
| 磁盘不足或无写权限 | 腾出空间或修复数据目录权限后重试；不要删除密钥或重建空库覆盖原数据 |
| 密钥无法解开 | 不覆盖旧目录，用便携备份在可用环境恢复；原账户损坏时本机备份可能也不可用 |
| 页面打不开 | 先启动应用；确认18765端口无其他程序占用；不要直接双击前端HTML |

照片不能检测隐藏过敏原、油盐糖、交叉接触或真实重量。基础库为USDA SR Legacy 2018的82项参考食品与30组合食谱，不是完整中餐数据库；嘌呤未知。疾病复杂、孕哺、未成年或无法可靠核对时暂停自动定量，仍可记餐。急救规则有表达覆盖限制，不能依赖应用判断是否存在急症；胸痛、呼吸困难、意识异常、严重过敏等请立即就医，必要时拨打120。本应用不诊断、不改药。

## 环境维护与验证

当前电脑已准备本地Python环境、前端构建、模型及运行时。正常使用无需Node、开发服务器或安装操作。离线Python安装包保存在 `.tools/wheels`；维护步骤见 `docs/installation.md`，不要移动或删除所依赖的Python运行环境。

开发维护可运行 `测试.cmd`。它执行后端全部测试（包含真实本地模型）、前端构建与Edge实际操作测试；所有测试使用独立目录。证据位于 `.test-output`，其中只含合成档案和许可测试照片，不是你的正式资料。

真实整机重启、另一Windows账户恢复、关闭网络适配器后的使用仍按验收表标待人工验证；进程重启和独立目录恢复已测试，不把两者混称。
