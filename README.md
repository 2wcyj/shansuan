# 膳算

膳算是一款个人营养与生活管理应用，将个人档案、饮食计划、实际摄入和每日感受连接起来，帮助你决定吃什么、回顾吃过什么，并根据反馈调整下一天的方案。

当前版本主要运行于 **Windows 64 位电脑**，无需登录。页面通过本机浏览器或 Edge 独立应用窗口打开；健康资料保存在电脑的独立加密文件中。本地 AI 准备完成后，日常使用不依赖云数据库、远程 AI 或外网。首次安装依赖、下载模型及安卓工具链需要联网。

> 当前提供源码项目，不是下载后即可直接运行的独立安装包。安卓版本是局域网伴侣端，需要电脑保持运行；尚不提供公网多用户服务、云同步或脱离电脑的独立手机端。

另有**尚未发布的云端多人版开发实现**：独立 Linux/FastAPI 服务、PostgreSQL 账户隔离、加密仓储及登录/敏感信息授权界面，并开始复用现有业务页面。它与下面介绍的 Windows 本机版分开运行，不会自动读取或迁移本机资料。照片、云端模型、备份恢复、完整前后端联调和生产安全验收仍未完成；暂不用于真实健康资料或朋友试用。架构和上线门槛见 [云端架构](docs/cloud-multiplayer-architecture.md)，前端发布准备见 [Netlify 说明](docs/netlify-deployment.md)。仅上传静态文件到 Netlify 不会获得可用的 API 或数据库。云端现已适配华为云 **RDS for PostgreSQL**、**DCS for Redis**、**OBS** 与 **KMS**，开通与部署步骤见 [华为云部署指导](docs/huawei-cloud-deployment.md)。

## 项目解决什么问题

- 根据目标、健康状况、过敏原和偏好筛选餐食，减少每天决定吃什么的负担。
- 区分“计划吃”和“实际吃过”，避免把推荐或商品浏览计入摄入。
- 将饮食、饮水、睡眠、运动和感受整理成 7 天或 30 天的阶段报告，保留缺失数据的真实状态。
- 将健康资料留在本机，提供加密备份与恢复，避免刷新或关闭浏览器后丢失数据。

本应用用于饮食记录和营养参考，不作医学诊断、不修改药物或治疗方案。营养数值和照片分析属于估算；复杂健康情况可能暂停自动定量推荐。

## 主要功能

| 模块 | 当前实现 |
| --- | --- |
| 个人档案 | 身体信息、生活状态、目标、健康情况、过敏原、口味、食物形态和烹饪偏好；区分未填写与明确无 |
| 每日饮食 | 条件允许时生成早餐、午餐、晚餐和可选加餐；展示分量、营养估算、来源、做法、时间、参考成本与替代方案；支持替换、跳过和修改分量 |
| 拍照分析 | 上传 JPG/PNG/WebP（最多 12MB）或使用可用摄像头，本地模型分析；修订食物和分量、重新计算，确认食用后记餐 |
| 智能问答 | 本地模型结合档案与近七天实际记录回答，展示参考条件；用户确认后才修改计划 |
| 饮食及生活记录 | 手动记餐、补记、修改、删除，自定义包装食品标签；记录饮水、睡眠、运动、体重和感受；可选的血压与静息心率记录，同日可多次 |
| 每日反馈与调整 | 快捷反馈，详细内容可选；检查明日方案，展示调整原因与营养变化，支持确认或恢复 |
| 阶段报告 | 查看 7 天或 30 天已记录摄入、饮水、生活状态和体重变化；缺失记录不补零 |
| 我的产品 | 本地产品目录、类别筛选、详情、编辑、隐藏、归档和可关闭的个性化推荐；明确标记自有产品及推广属性 |
| 保存与备份 | 提交后写入加密存储；手动保存创建本机恢复点；密码加密便携备份、整体恢复、JSON/CSV 可阅读导出和删除数据 |
| 外观 | 深色、浅色及跟随系统主题 |
| 安卓伴侣端 | 导入连接文件，通过同一局域网 HTTPS 网关访问电脑上的膳算 |

产品初始目录包含六项“千人千植”概念产品，来自计划书示意，**不代表已上市商品或正式标签**。配料、过敏原和关键营养资料未核实时，不给出“适合你”的结论，不参与营养统计。已核实产品仍需主动加入计划、确认实际食用与分量后才计入摄入，不自动替换原有餐食。

## 安装方法

### 1. 准备环境与源码

- Windows 64 位、Python **3.12**（以下命令通过 `py -3.12` 调用）。存储依赖 Windows DPAPI，暂不支持直接在 macOS/Linux 运行。
- Node.js 与 pnpm：用于前端安装和构建；当前开发环境使用 Node 24。构建后正常运行不需要 Node 或前端开发服务器。
- Microsoft Edge：桌面独立应用窗口及浏览器测试需要；普通浏览器入口可使用本机浏览器。
- 在 GitHub 仓库页面复制实际地址后克隆，或下载源码 ZIP 并解压。以下命令均在项目根目录的 PowerShell 中执行。

仓库不包含 `.venv`、`node_modules`、前端 `dist`、`.tools` 中的模型/运行时或 APK，需要自行准备。尚未确定适用于所有设备的最低内存和性能要求，CPU 模型加载与分析可能较慢。

### 2. 安装 Python 依赖

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

依赖包含 FastAPI、SQLCipher、cryptography 等。加密驱动安装或加载失败时需要先解决兼容问题，应用不会降级为明文数据库。已有离线 wheel 缓存可按 [安装说明](docs/installation.md) 离线安装；新克隆仓库不附带缓存。

### 3. 安装并构建前端

先确保 pnpm 已安装并可用，然后执行：

```powershell
cd app/frontend
pnpm install --frozen-lockfile
pnpm run build
cd ../..
```

产物在 `app/frontend/dist/`，由 Python 服务提供。不要直接双击其中的 HTML。

### 4. 启动基础功能

```powershell
.\.venv\Scripts\python.exe app/scripts/run.py --no-model
```

浏览器打开 `http://127.0.0.1:18765/`。可先使用档案、规则饮食推荐、手动记录、反馈、报告、产品目录与备份。照片 AI 识别和模型问答需准备下一节的模型，否则显示未就绪状态。

### 5. 可选：准备本地 AI

应用固定使用 `qwen3-vl:2b-instruct`，模型接口为 `127.0.0.1:11439`。日常启动不自动下载模型。

下载 Windows CPU 运行时：

```powershell
.\.venv\Scripts\python.exe app/scripts/fetch_resources.py ollama
```

脚本从 Ollama 官方 GitHub 发布页获取当时的最新版本。原交付环境曾使用 Ollama 0.40.6；新下载版本需验证兼容性，不能沿用旧版本测试结论。

在项目根目录的 PowerShell 中启动用于准备模型的服务：

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11439'
$env:OLLAMA_MODELS = Join-Path (Get-Location).Path '.tools/models'
$env:OLLAMA_NO_CLOUD = '1'
.\.tools\ollama\ollama.exe serve
```

保持窗口运行，在另一个 PowerShell 窗口进入同一项目根目录执行：

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11439'
$env:OLLAMA_MODELS = Join-Path (Get-Location).Path '.tools/models'
$env:OLLAMA_NO_CLOUD = '1'
.\.tools\ollama\ollama.exe pull qwen3-vl:2b-instruct
.\.tools\ollama\ollama.exe list
```

模型下载需要联网及足够磁盘空间。完成后停止准备用的 `serve` 窗口及先前启动的基础应用，再双击 `启动.cmd`，由应用启动本地 AI。模型许可见 [Qwen3-VL 许可](docs/third-party/qwen3-vl-license.txt)。

## 使用方法

1. 双击 `启动.cmd` 打开浏览器版本，按引导建档，明确确认健康与过敏信息；未填写不等于“无”。
2. 首页查看今日已记录摄入及下一餐，进入“今日饮食”核对食物、分量与替代方案。不满足安全条件时说明限制，不强行生成。
3. 吃过后核对实际食物和分量再确认，也可手动记餐。替换或修改计划不会增加实际摄入。
4. 按需记录饮水、睡眠、运动、体重及每日反馈，检查明日调整，查看阶段报告（7 或 30 天）。
5. 首页“更多”提供各模块与“手动保存”；个人档案内管理备份、恢复、导出和删除。
6. 需要桌面入口时运行 `安装桌面应用.cmd`，以后双击桌面的“膳算”。快捷方式依赖原项目路径、Python 环境及 Edge，不是独立 EXE。
7. 关闭页面不会删除数据，也不一定停止后台；需要停止服务时运行 `停止.cmd`。

### 安卓手机连接（可选）

最低目标版本为 Android 8.0（API 26），需要电脑与手机在同一局域网，电脑持续开机运行。

1. 准备工具链并构建（首次需要联网）：

   ```powershell
   .\.venv\Scripts\python.exe app/scripts/prepare_android.py
   .\构建安卓安装包.cmd
   ```

2. 将生成的 `手机安装包/膳算-Android.apk` 私下传到手机安装；安装包及本地签名密钥不在源码仓库中。
3. 启动电脑膳算，再运行 `启动手机连接.cmd`。多个网卡时使用 `启动手机连接.cmd --host 电脑局域网IPv4`。
4. 将电脑桌面 `膳算手机连接/电脑连接.shansuan` 传到手机，在安卓膳算中点击“导入电脑连接文件”。连接文件含访问凭据，不要公开或提交到 Git。
5. 保持电脑服务和连接窗口运行。防火墙若询问，仅允许专用网络访问，无需关闭防火墙。

详见 [手机安装包说明](手机安装包说明.md)。APK 构建和签名已在原环境验证，实机安装、相机及 Wi-Fi 连通仍需设备验收。当前包装脚本用 `S:` 路径别名处理中文路径；若已存在其他用途的 `S:` 驱动器需先检查冲突。

## 输入输出示例

以下输入仅用于说明流程，不是真实用户资料，不保证任何档案都生成相同餐食或固定 AI 文案。

### 示例一：根据档案生成计划

- **输入**：30 岁、女、165cm、60kg，上班族，主要目标“日常营养均衡”，健康及过敏状态均选“明确无”，偏好清淡、家庭烹饪。
- **操作**：保存并确认档案，进入“今日饮食”。
- **输出**：条件允许时生成当日四餐候选，展示分量、营养估算、理由和替代方案；实际饮食记录仍为空，推荐不会算成已摄入。

### 示例二：根据包装标签计算实际摄入

- **输入**：创建自定义食品，按真实包装填写每 100g 能量 200kcal、蛋白质 10g、脂肪 4g、碳水 31g；其他未知指标留空。此处数字仅演示计算，不属于内置商品标签。
- **操作**：记录实际食用 50g 并保存。
- **输出**：该条记录估算为 100kcal、蛋白质 5g、脂肪 2g、碳水 15.5g；其他指标仍为未知，不填为 0。保存后计入所选日期的实际摄入。
- **单位**：标签为 kJ 时需先除以 4.184 转为 kcal；自定义食品按每 100g 输入。

### 示例三：问答与资料不足

- **输入**：“我今天蛋白质够不够？”
- **输出**：模型就绪时读取档案和近七天实际记录，展示参考条件，据已知记录回答。未完整记录或营养资料不全时，不把已记录部分当作全天摄入，也不凭空断言达标。
- **异常**：模型未就绪或任务失败会显示真实状态，不用虚构回复冒充分析。

### 示例四：未核实产品

- **输入**：打开初始目录中的“千人千植”低脂蛋白棒。
- **输出**：展示计划书示意、待核实状态及商业属性。示意营养数据不能作为健康匹配和摄入统计依据，浏览商品不会生成饮食记录。

## 本地数据与备份

默认目录为 `%LOCALAPPDATA%\MyNutritionAssistant`，个人档案页显示实际路径。数据库使用 SQLCipher，照片与产品附件加密保存，主密钥由当前 Windows 账户的 DPAPI 保护。刷新、关闭浏览器或清除站点数据不会删除这些独立文件；主题偏好另存于浏览器。

- 提交操作保存数据；“手动保存”另建本机加密恢复点。
- 本机 `.mnal` 备份依赖 Windows 账户。跨账户/电脑使用密码加密的 `.mnab` 便携备份，密码至少 10 字符，无法找回。
- 恢复先检查，再输入“整体替换”确认，属于整体恢复而非合并。
- JSON/CSV 是**未加密的查阅副本**，不是可恢复备份。
- 安卓模式下健康数据仍在电脑，手机保存加密配对信息；备份导出、恢复、删除等管理操作需在电脑端完成。
- 不要提交个人数据、照片、备份、连接文件及签名密钥。`.gitignore` 不等于所有文件和 Git 历史均已完成隐私审查。

无需应用登录意味着当前 Windows 用户可以访问应用；磁盘加密不隔离已登录账户。运行期不接入广告 SDK、在线支付或营销数据服务。

## 云端部署（华为云）

云端版按赛题要求接入华为云托管服务：

| 服务 | 作用 | 配置变量 |
| --- | --- | --- |
| RDS for PostgreSQL | 账户、业务数据、行级安全与迁移 | `DATABASE_URL`、`MIGRATION_DATABASE_URL` |
| DCS for Redis | 多实例共享会话与登录限流，故障时回退 PostgreSQL | `REDIS_URL` |
| OBS | 存放应用层加密后的照片密文 | `OBS_PROVIDER`、`OBS_REGION_ID`、`OBS_BUCKET` |
| KMS | 包封每账户数据密钥 | `KMS_PROVIDER=huawei`、`KMS_REGION_ID`、`KMS_KEY_ID` |

```powershell
# 构建并推送镜像到 SWR（在 Linux/CI 环境）
$env:SWR_REGION = 'cn-north-4'
$env:SWR_ORGANIZATION = 'your-org'
$env:IMAGE_TAG = '0.1.0'
bash deploy/huawei/build-and-push.sh
```

完整步骤（含 RDS/DCS/OBS/KMS 开通、迁移、ECS 启动、健康检查与验证清单）见 [华为云部署指导](docs/huawei-cloud-deployment.md)。环境变量模板见 [`deploy/cloud/.env.example`](deploy/cloud/.env.example)。

## 开发与验证

技术栈：React 19、TypeScript、Vite、FastAPI、SQLCipher、Windows DPAPI、AES-GCM、本地 Ollama；安卓端使用 Java WebView 和 HTTPS 局域网网关。

```text
app/backend/     接口、业务规则、加密存储、本地 AI 任务
app/frontend/    页面、主题、前端构建
app/resources/   食物/食谱参考数据、来源和图标
app/android/     安卓伴侣端源码
app/scripts/     启动、桌面入口、安装准备、测试与打包
app/tests/       后端测试和浏览器检查脚本
docs/            使用、安装、设计、计划及验收文档
```

后端测试及前端类型检查/生产构建：

```powershell
.\.venv\Scripts\python.exe -m pytest app/tests -q
cd app/frontend
pnpm run build
cd ../..
```

后端全套包含真实本地模型测试，需先准备指定运行时和模型，不应跳过失败项来宣称全部通过。`测试.cmd` 还编排构建与真实 Edge 操作；**目前编排和浏览器脚本包含原开发电脑的 Codex Node/Playwright 路径约定，并非通用的一键测试环境**。其他电脑需调整工具路径并准备 Playwright 和 Edge；正式使用不依赖 Codex。

测试使用独立目录和合成档案，输出在 `.test-output/`。原环境曾完成 95 项后端测试及前端构建；新环境是否通过以实际执行为准。

## 当前限制与许可

- 基础库是 USDA SR Legacy 2018 的 82 项参考食品和 54 组合食谱，不是完整中餐数据库；嘌呤等未知指标留空。
- 照片不能可靠判断重量、隐藏配料、油盐糖或交叉接触，不是过敏安全证明。复杂疾病、孕哺、未成年等情况不自动给出医学适用性结论。
- 报告支持 7 天与 30 天窗口，尚未实现 3/14 天等自定义窗口；多用户、公网服务、云同步、在线支付及 iOS 安装包仍未实现。
- 真实整机重启、物理断网、另一 Windows 账户恢复和安卓实机体验仍需设备验收。
